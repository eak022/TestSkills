3. กรอก UID ในช่อง Player ID แล้วกด OK เซิร์ฟเวอร์ `Empire#239` เปลี่ยน UID ได้ และมีรายการบัญชีที่เคยใช้ (Recently used Player ID)

5. เลือกแถว **BitCash** แล้วกด Pay

## สิ่งที่คนตรวจอยากเห็น

ค่าเริ่มต้นของ `bun run bot:worker` ยังเป็น simulator ไม่ซื้อของจริง  
ลำดับก่อนจ่ายดูได้จาก `bun run bot:aoem-dry-run`

1. **แนวทางเขียนบอท** Playwright เปิดร้านญี่ปุ่น ล็อกอิน Midasbuy จาก `.env` กรอก UID `5250140737488366145` ตรวจเซิร์ฟเวอร์ `Empire#239` เลือกเฉพาะแพ็ก 99+109 Coin / 146 JPY เลือก BitCash แล้วเลือก Pay with MyBitCash จากนั้นรอ OTP ที่คนวางใน `data/aoem-otp.txt`
2. **ปัญหาที่เจอและทางแก้** cookie หมดให้ล็อกอินใหม่ทุกออเดอร์ CAPTCHA ไม่แก้และคืน `CAPTCHA` เพื่อให้คิวหน่วง selector เปลี่ยนหรือ region ไม่ใช่ญี่ปุ่นเป็นความล้มเหลวถาวร OTP หมดเวลาแล้วไม่กดจ่าย
3. **เช็กยอด** อ่าน `お支払い額` กับ `残高` ก่อน-หลัง ส่วนต่างต้องเท่ากับ 146 JPY และประวัติ Midasbuy ต้องมีแพ็กเดียวกัน จึงเดินสถานะสำเร็จ ถ้ายอดลดแล้วแต่ประวัติยังไม่ขึ้น จะไม่กดจ่ายซ้ำ

ติดตั้งเบราว์เซอร์ก่อนโหมดจริง `bun add playwright && bunx playwright install chromium`

## เช็กยอดหลังทำรายการเสร็จ

ใช้สามแหล่งเทียบกัน ห้ามถือว่าจ่ายสำเร็จจากหน้า Bitcash อย่างเดียว

1. **ประวัติออเดอร์ Midasbuy** เปิดหลังจ่าย แล้วจับคู่แพ็ก 99+109 Coin กับราคา 146 JPY ของรายการนี้
2. **ใบเสร็จ Bitcash** หลัง OTP อ่าน `請求番号` (Invoice No.), `お支払い額` (จำนวนที่จ่าย) และยอดคงเหลือด้านล่าง ส่วนต่างก่อน-หลังต้องเท่ากับ 146 JPY ของแพ็กนี้ ถ้ายอดไม่ลด ถือว่ายังไม่จ่าย ตัวเลขตัวอย่างบนสไลด์เป็นคนละรายการ ไม่ใช้เป็นยอดของออเดอร์นี้
3. **ออเดอร์ในระบบนี้** เทียบกับ `orderNo` ถ้ายอด Bitcash ลดและประวัติ Midasbuy ขึ้นรายการนี้ ให้เดินสถานะเป็นเติมสำเร็จ ถ้าจ่ายแล้วแต่เหรียญยังไม่เข้า ให้รอ webhook หรือเครดิตตามเคสผู้ให้บริการล่มของโจทย์ที่ 1 ไม่กดจ่ายซ้ำ

ระหว่างรอผล ให้ถือ lease ของออเดอร์ไว้ หมดเวลายังเช็กยอดไม่จบจึงค่อย retry

## กติกา

- ค่าเริ่มต้นคือ simulator / dry-run ห้ามซื้อจริงใน dev หรือ CI
- โหมดจริงต้อง opt-in ทั้ง `BOT_MODE=real` และ `BOT_REAL_ENABLED=true`
- รหัสผ่าน Midasbuy และ Bitcash อยู่ใน `.env` เท่านั้น ห้ามเก็บรหัส OTP จากสไลด์มาใช้ซ้ำ
- ซื้อจริงได้แพ็กเดียว: 99+109 Coin / 146 JPY
- บอทอยู่ที่ `oxide-monitor-candidate-pack/bot/` ตัวจริงคือ `purchase.ts` จะกดจ่ายก็ต่อเมื่อ `BOT_MODE=real` และ `BOT_REAL_ENABLED=true` และเวลาไทยอยู่ในช่วง 12:00–17:00 คำสั่ง stop จากมอนิเตอร์ทำให้ `acceptingOrders` เป็นเท็จแล้วบอทไม่รับงาน

## สิ่งที่เห็นบนร้านญี่ปุ่น

ไล่ใน Chrome ที่ล็อกอินแล้ว จนถึงหน้าต่าง **セキュリティー支払い** แล้วหยุดก่อนปุ่ม **お支払う**

- ผู้เล่น `Inblackcs1` UID `5250140737488366145`
- สรุปออเดอร์ขึ้นชื่อแพ็ก **99至高コイン** ราคา **146円** (ราคาเดิมขีดฆ่า 456円) ของแถมที่เห็นคือ **10至高コイン** ป้ายโจทย์ **99+109 Coin** ไม่ได้โชว์เป็นข้อความบนสรุปนี้ ก่อนจ่ายจริงต้องเทียบกับการ์ดแพ็กที่กด
- ช่องทางที่เห็น: บัตรเครดิต, PayPay, WebMoney, au PAY, **BitCash**, PayPal, WeChat Pay, NET CASH
- แถว BitCash เป็นแถวข้อความ `BitCash` กดเลือกได้ ขอบเป็นสีฟ้าเมื่อถูกเลือก ไม่มีป้ายโบนัสเหรียญแบบ PayPal / WeChat
- เบราว์เซอร์ในแชทล็อกอินไม่ผ่าน ได้ `System busy (567)` ใช้ Chrome บนเครื่องที่ล็อกอินเอง

### ทดสอบพรุ่งนี้ช่วง 12:00–17:00 น. เวลาไทย

คืนนี้อยู่นอกช่วง จึงยังไม่ขอ OTP และยังไม่กดจ่าย ตรวจความพร้อมได้เลย

```bash
bun run bot:aoem-otp
```

พรุ่งนี้เมื่อเข้าช่วงแล้ว

1. ใส่ `MIDASBUY_EMAIL` `MIDASBUY_PASSWORD` `BITCASH_ID` `BITCASH_PASSWORD` ใน `.env` และตั้ง `BOT_MODE=real` กับ `BOT_REAL_ENABLED=true`
2. ติดตั้งเบราว์เซอร์ถ้ายังไม่มี `bun add playwright && bunx playwright install chromium`
3. รัน `BOT_KEY=bot_คีย์ bun run bot:worker` บอทจะไปถึงหน้า OTP แล้วหยุดรอ ไม่กด `お支払う`
4. เปิด Outlook ของ HR แล้ววางรหัสตัวเลข 4–8 หลักลงไฟล์ `data/aoem-otp.txt` ไฟล์นี้ไม่เข้า git และถูกลบหลังอ่าน
5. บอทรอได้ 10 นาที ถ้าไม่มีรหัสจะไม่กดจ่าย

บันทึกหน้าจอที่เปิดดูจริงอยู่ที่ [`ui-observed.md`](ui-observed.md) เขียนบอทจากไฟล์นั้น ขั้นที่ไฟล์นั้นบอกว่ายังไม่เห็นห้ามเดา selector

### ยังไม่ทำ

- จ่ายจริงหนึ่งครั้งในช่วงนั้น แล้วเทียบ Invoice กับยอด Bitcash ก่อน-หลัง
