# 2. เคสปัญหา 5 ข้อ

ทุกเคสเริ่มจากออเดอร์ใหม่สถานะ `PENDING_PAYMENT` วิธีสร้างซ้ำขั้นตอน 1.1 ใน [01-order-tracking.md](01-order-tracking.md) แล้วใช้ `x-event-id` กับ `providerRef` ที่ยังไม่เคยใช้

หยุด worker ตัวเก่าก่อนเปลี่ยน `BOT_FAULT`

## ข้อ 1 — บอทล่ม แล้วออเดอร์ไม่ค้างถาวร

```bash
BOT_KEY=bot_คีย์ของbot-04 BOT_FAULT=silent bun run bot:worker
```

log ต้องมี `"fault":"silent"`

จ่ายเงินด้วย event ใหม่ เช่น `evt_silent_001` และ `providerRef` ใหม่ ได้ `outcome: queued`

timeline ช่วงแรกจบที่ `Claimed by bot-04` สถานะ `IN_PROGRESS` worker จะพิมพ์ `simulating_crash` แล้วเงียบ 150 วินาที

รอให้เลย 2 นาทีหลังเวลา claim หรือให้แอดมินเรียก `POST /api/v1/orders/maintenance/run` หลังเลย 2 นาทีนั้น

timeline ต้องมี `Lease expired, requeue retry 1` สถานะกลับเป็น `QUEUED`

ถ้าปล่อย worker ตัวเดิมรันต่อ มันจะ claim แล้วเงียบซ้ำ จนครบ 3 ครั้ง แล้วเป็น `DELAYED` บรรทัดสุดท้ายเป็น `Lease expired after 3 retries — DELAYED, notify admin`

แจ้งแอดมินอยู่ในตาราง `systemAlert` ค่า `type = CLAIM_EXHAUSTED` ยังไม่มี endpoint รายการแจ้งเตือน เปิดดูด้วย

```bash
bunx prisma studio
```

ออเดอร์ `DELAYED` ยังโชว์ใน `GET /api/v1/orders?tab=current`

## ข้อ 2 — บอทสองตัวแย่งออเดอร์เดียวกันไม่ได้

หยุด worker ทั้งหมด ออกคีย์ให้เครื่องที่สอง (แอดมิน) `POST /api/v1/bots/bot-05/api-key` ถ้า 404 ให้ `POST /api/v1/bots` สร้าง `bot-05` ก่อน

เปิดสองเทอร์มินัล

```bash
BOT_KEY=คีย์bot-04 bun run bot:worker
BOT_KEY=คีย์bot-05 bun run bot:worker
```

สร้างออเดอร์เดียว แล้วยิง webhook `PAID` ครั้งเดียว

timeline ต้องมี `Claimed by` เพียงบรรทัดเดียว ไม่ว่าจะเป็น bot-04 หรือ bot-05 อีกเครื่องไม่ได้ claim ออเดอร์เดียวกันซ้ำ สุดท้ายมี `COMPLETED` แถวเดียว

## ข้อ 3 — Webhook ซ้ำ ช้า และผิดลำดับ

ใช้ token ไม่เกี่ยวกับ endpoint นี้

**ซ้ำ:** ยิง webhook ที่สำเร็จไปแล้วด้วย `x-event-id` เดิม ได้ `replayed: true` และสถานะไม่เปลี่ยน

**ผิดลำดับ:** ยิง `PAID` ใส่ออเดอร์ที่ `COMPLETED` แล้ว แต่ใช้ `x-event-id` ใหม่ ได้ `outcome: ignored_out_of_order` และ `replayed: false`

**ช้าหลังหมดอายุ:** สร้างออเดอร์แล้วไม่จ่าย รอเกิน 15 นาที (หรือรอจนเลย `expiresAt`) แล้วให้แอดมินเรียก `POST /api/v1/orders/maintenance/run` สถานะต้องเป็น `EXPIRED`

จากนั้นยิง `PAID` ด้วย `x-event-id` ใหม่และ `providerRef` ใหม่ คาดหวัง

```json
{ "outcome": "credited", "replayed": false }
```

timeline เป็น `EXPIRED → REFUNDED` เหตุผลขึ้นต้น `Late webhook after expiry` ระบบไม่ส่งออเดอร์นี้เข้าคิวเติมเกม

**ลายเซ็น (ทำเมื่อตั้ง `WEBHOOK_SECRET`):** ไม่ส่ง `x-webhook-signature` ได้ `401` ส่งค่ามั่วได้ `401` ถ้าไม่ตั้ง secret ใน dev คำขอที่ถูกต้องผ่านได้โดยไม่ต้องมีลายเซ็น

## ข้อ 4 — เติมไม่สำเร็จ แล้วแก้ UID หรือคืนเงิน

หยุด worker แล้วรัน

```bash
BOT_KEY=bot_คีย์ของbot-04 BOT_FAULT=uid_invalid bun run bot:worker
```

สร้างออเดอร์ใหม่ จ่ายด้วย event ใหม่

timeline ต้องมี `IN_PROGRESS → FAILED` เหตุผล `Permanent top-up error: UID_INVALID` ไม่มีการ retry

**แก้ UID แล้วเข้าคิวใหม่** สลับเป็น token ลูกค้าเจ้าของออเดอร์

`POST /api/v1/orders/{orderNo}/fix-uid`

```json
{ "playerUid": "5250140737488366145" }
```

สถานะกลับเป็น `QUEUED` ใช้ได้เฉพาะ `FAILED` หรือ `DELAYED`

ถ้า worker ยังเป็น `uid_invalid` มันจะรับแล้ว `FAILED` อีก หยุดมันก่อนถ้าจะดูทางคืนเงินอย่างเดียว

**คืนเงิน** สลับเป็น token แอดมิน

`POST /api/v1/orders/{orderNo}/refund`

```json
{ "reason": "ลูกค้าขอคืนเงิน" }
```

สถานะเป็น `REFUNDED` timeline มีชื่อแอดมินในเหตุผล ลูกค้าเรียก endpoint นี้เองได้ `403`

ทาง provider ล่มใช้ `BOT_FAULT=provider_down` แทน ผลคือคืนคิวแบบ backoff ไม่ใช่ `FAILED` ทันที รหัสถาวรมีแค่ `UID_INVALID`, `UID_BANNED`, `PACK_NOT_FOUND`

## ข้อ 5 — QR หมดเวลา และคิวค้างเกิน SLA

**หมดเวลาจ่าย:** สร้างออเดอร์แล้วไม่ยิง webhook รอเกิน 15 นาที แล้วให้แอดมินเรียก `POST /api/v1/orders/maintenance/run`

สถานะเป็น `EXPIRED` timeline มี `PENDING_PAYMENT exceeded QR/payment TTL` เรียก maintenance ซ้ำได้ ออเดอร์ที่หมดอายุไปแล้วไม่ถูกย้ายซ้ำ

**คิวเกิน 10 นาที:** หยุด worker ทุกตัว สร้างออเดอร์แล้วยิง `PAID` ให้ค้างที่ `QUEUED` อย่าให้ใคร claim

รอเกิน 10 นาที แล้วเรียก `POST /api/v1/orders/maintenance/run` อีกครั้ง

ออเดอร์ยังเป็น `QUEUED` (ไม่ได้ถูกปิดเอง) และตาราง `systemAlert` มีแถว `type = QUEUED_SLA` ของ `orderNo` นั้น เรียกซ้ำไม่เพิ่มแถวใหม่
